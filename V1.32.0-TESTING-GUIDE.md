# v1.32.0 Testing Guide — Proposal Overhaul + Portal Fixes

**Plugin version to upload:** `el-core-v1.32.0.zip` (in Downloads)
**Upload at:** WordPress Admin → Plugins → Add New → Upload Plugin

---

## Before You Start

1. Upload and activate v1.32.0
2. WordPress will run the DB migration automatically on first load (adds `annual_platform_fee`, `first_payment_amount`, `final_payment_amount` columns to `el_es_proposals`)
3. Have a test project at Stage 3 (Proposal) ready. You'll need one at Stage 4 as well.

---

## Bug 1 — Empty-State "New Proposal" Button

**Where:** Admin → Expand Site → Project Detail → Phase 3 tab (when no proposals exist yet)

**Test:**
1. Open a project that has no proposals yet
2. Click the Phase 3 tab
3. You should see the empty state: "No proposals yet" with a green **New Proposal** button inside the table area
4. Click that green button
5. **Expected:** A new proposal is created and the page reloads showing the new draft in the table
6. **Also verify:** The white "New Proposal" button in the card header (top right of the card) still works the same way

**Pass criteria:** Both buttons create a proposal. No "does nothing" behavior.

## Bug 2 — Structured Payment Fields

### 2A — Proposal Edit Modal Fields

**Where:** Admin → Project Detail → Phase 3 → Edit a proposal (pencil icon)

**Test:**
1. Open an existing proposal for editing
2. **Expected modal fields:**
   - Final Price ($) — single price field
   - Annual Platform Fee ($) — new field
   - First Payment (25%) Amount ($) — new field with help text
   - Final Payment (75%) Amount ($) — new field with help text
   - Terms & Conditions — still present
3. **Budget Low / Budget High fields should be GONE** from the modal
4. **Payment Terms textarea should be GONE** from the modal

**Pass criteria:** 4 pricing fields present, 3 old fields absent.

### 2B — Auto-Calculation

**Test:**
1. In the edit modal, type `10000` in the Final Price field
2. **Expected:** First Payment auto-fills to `2500`, Final Payment auto-fills to `7500`
3. Now manually type `3000` in the First Payment field
4. **Expected:** First Payment stays at `3000` (override respected), Final Payment stays at `7500`

**Pass criteria:** Auto-calc works on price input. Manual override sticks.

### 2C — Portal Payment Breakdown

**Where:** Client portal → Stage 3 (when proposal is sent)

**Test:**
1. Set Final Price = `15000`, Annual Platform Fee = `1200`, save
2. Send the proposal to the client
3. View the portal as the client/DM
4. Scroll to "Your Investment" section
5. **Expected display:**
   ```
   Development Investment        $15,000
     First Payment (25%) — due upon wireframe approval    $3,750
     Final Payment (75%) — due upon delivery              $11,250
   Annual Platform Fee           $1,200/year
   ```

**Pass criteria:** Structured breakdown shows correct amounts with indent on sub-lines.

### 2D — AI Generation

**Test (if AI is configured):**
1. Open a project with a locked definition and a proposal that has a Final Price set
2. Open the proposal edit modal → click "Generate with AI"
3. **Expected:** The Investment section text references the actual dollar amounts (not "TBD" or placeholder ranges)

## Bug 3 — Terms & Conditions Formatting

**Where:** Client portal → Stage 3 → scroll to bottom of proposal → click "Terms & Conditions"

**Test:**
1. View the portal as a client when proposal is sent
2. Scroll to the bottom of the proposal document
3. Click "Terms & Conditions" to expand it
4. **Expected:**
   - Each numbered section (1. Scope of Work, 2. Client Responsibilities, etc.) shows as a **bold heading**
   - The paragraph text below each heading is readable and separated
   - NOT one giant blob of text
5. **Check section spacing** — there should be visual breathing room between sections

**Pass criteria:** T&C renders as distinct numbered sections with bold headings, not one unformatted paragraph.

## Bug 4 — PDF Download Button

**Where:** Client portal → Stage 3 → proposal document

**Test:**
1. View the portal as a client/DM when proposal is sent
2. Look for a **"Download PDF"** button at the top-right of the proposal document
3. Click it

   - Font is serif (Georgia), black on white

   - T&C details element is open/expanded (content visible in print)

**Pass criteria:** Print button visible, print preview shows clean letterhead layout with no portal chrome.

## Bug 5 — Accepted Proposal → Info Card

### 5A — Proposal Info Card in Stage Cards Row

**Where:** Client portal → any stage 3+ (when a sent or accepted proposal exists)

**Test:**
1. Send a proposal to the client
2. View the portal (any stage)
3. Look at the **info cards row** (the row with Deliverables, Feedback, Project Definition)
4. **Expected:** A "Proposal" card appears in this row
   - Shows "Pending" badge if proposal is sent but not yet accepted
   - Shows "Accepted" badge once accepted
5. Click the Proposal card
6. **Expected:** A modal opens showing the full proposal document (same letterhead layout, with Download PDF button)

**Pass criteria:** Card appears, badge correct, modal shows full proposal.

### 5B — Greyed-Out Card When No Proposal

**Test:**
1. View the portal on a Stage 3+ project that has NO sent proposal yet
2. **Expected:** A greyed-out/disabled "Proposal" card shows with "Not yet sent" text
3. It should NOT be clickable

**Pass criteria:** Disabled card shows when no proposal is sent.

### 5C — Accepted Proposal Shows Condensed View Past Stage 3

**Test:**
1. Accept a proposal (DM accepts via portal)
2. Advance the project to Stage 4 (admin: advance stage)
3. View the portal as the DM/client at Stage 4
4. Scroll to the global sections area (below the stage content)
5. **Expected:** Instead of the full proposal inline, see only:
   > "Proposal [Accepted badge]"
   > "Accepted on [date] by [name]. View the full proposal using the Proposal card above."
6. **NOT expected:** The full proposal document rendered inline at Stage 4+

**Pass criteria:** Past Stage 3, only the brief accepted line shows — no inline proposal wall of text.

## Known Limitations (Not Bugs)

- **Stage 4 guided questions form** is NOT in this version — that's Step C, coming in v1.32.x. Stage 4 shows the placeholder only.
- **Existing proposals** that had `payment_terms` free-text entered will lose that text from the admin modal (the field was removed). The value is still in the DB but not editable — it won't be shown to clients since the portal now uses the structured fields. If any proposals had important custom payment terms, they should be migrated to the `section_investment` narrative field.
- The "Budget Low / Budget High" range display in the portal investment section is a **fallback only** — it shows if `final_price` is 0. Once a final price is set, only the structured breakdown shows.
