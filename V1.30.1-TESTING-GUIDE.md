# v1.30.1 Testing Guide — Single Project, Start to Finish

**Plugin:** EL Core v1.30.1  
**Approach:** One project, tested from creation through definition approval. Do NOT jump back and forth. Follow these steps in order.

---

## Setup Before You Start

1. Upload `el-core-v1.30.1.zip` via WordPress Admin → Plugins → Add New → Upload Plugin
2. Verify plugin shows "EL Core 1.30.1"
3. Have three users ready:
   - **Admin** — your WP admin account
   - **DM** — a test user who will be the Decision Maker on the portal
   - **Contributor** — a second test client user

---

## Step 1 — Create a New Project (as Admin)

1. Go to WP Admin → Expand Site → Create Project
2. Fill in project name (e.g., "Test Project 1.30") and client name
3. Click **Create Project**

**Expected:**
- [ ] Project is created and you're taken to the project detail page
- [ ] No blank white page

---

## Step 2 — Save the Qualification Intake (as Admin)

1. You should be on the project detail page, Phase 1 (Qualification) tab
2. Fill in the **Project Goal** field with a few sentences
3. Set the **Discovery Call Date** to today or any date
4. Add something in **Internal Notes**
5. Click **Save**

**Expected:**
- [ ] Button shows "Saving…" briefly, then shows "Saved ✓" for 2 seconds
- [ ] No page reload, no blank white page
- [ ] Refresh the page — your saved values are still there

---

## Step 3 — Add Stakeholders (as Admin)

1. Click the **Stakeholders** utility tab at the top
2. Click **Add Stakeholder**
3. Search for your DM test user by name or email, select them
4. Set Role to **Decision Maker**, click Add

**Expected:**
- [ ] No HTTP 400 error
- [ ] Page reloads, DM user appears with green "Decision Maker" badge

5. Click **Add Stakeholder** again
6. Search for your Contributor test user, add them as **Contributor**

**Expected:**
- [ ] Contributor appears with blue "Contributor" badge
- [ ] Two stakeholders total in the list

7. Try the **Make Contributor / Make Decision Maker** toggle on one of the users

**Expected:**
- [ ] No HTTP 400 error
- [ ] Page reloads, role badge updates correctly

---

## Step 4 — Advance to Stage 2 (Discovery)

1. Click **Advance to Next Stage** (top right of project detail)
2. Confirm the advance

**Expected:**
- [ ] Project moves to Stage 2: Discovery
- [ ] Phase 2 (Discovery) panel is now active

---

## Step 5 — Paste Transcript and Process (as Admin)

1. In Phase 2 (Discovery), paste any block of text into the **Transcript** textarea
2. Click **Process with AI**

**Expected:**
- [ ] AI extracts definition fields and populates them
- [ ] You can review and edit the extracted fields
- [ ] Click **Save Definition** — shows success message

---

## Step 6 — Send Definition for Review (as Admin)

1. In Phase 2, click **Send to Client for Review**
2. Set a deadline 7 days from now
3. Click **Send for Review**

**Expected:**
- [ ] Status badge changes to "Sent for Review" (blue)
- [ ] "Send to Client for Review" button disappears
- [ ] "Reset to Draft" button appears (ghost style)

---

## Step 7 — Contributor Reviews (log in as Contributor)

1. Log in as the Contributor user
2. Go to the client portal page for this project
3. Scroll to the **Project Definition — Review** section

**Expected:**
- [ ] Review section loads (not blank, not loading forever)
- [ ] All definition fields are shown with their values
- [ ] Edit button next to each field
- [ ] "+ Add comment" button and "✓ Looks good" / "Needs revision" verdict buttons per field

4. Click **"✓ Looks good"** on the **Site Description** field

**Expected:**
- [ ] Button highlights green (active state)
- [ ] The review section reloads in-place
- [ ] The Site Description field shows **one** checkmark next to your name — NOT two

5. Click **"+ Add comment"** on the **Primary Goal** field
6. Type a comment and click Post

**Expected:**
- [ ] Comment posts without needing a page refresh
- [ ] Comment appears below the field immediately

7. Now click **"✓ Looks good"** on the **Primary Goal** field

**Expected:**
- [ ] Verdict saves in-place
- [ ] Section reloads

8. Click **"+ Add comment"** on the **Primary Goal** field AGAIN (after the verdict reload)

**Expected:**
- [ ] Comment form opens — NO page refresh needed
- [ ] Post the comment — it saves successfully

---

## Step 8 — DM Reviews and Clicks "Needs Revision" (log in as DM)

1. Log in as the DM user
2. Go to the client portal for this project
3. Scroll to the Project Definition review section

**Expected:**
- [ ] Review section loads with all fields
- [ ] "Make Final Decision" section is visible at the bottom (DM only)

4. Without selecting any verdicts, type a note: "Please clarify the primary goal and secondary goals."
5. Click **"Needs Revision"**

**Expected:**
- [ ] No page reload to a closed/stranded state
- [ ] Review UI reloads in-place
- [ ] A **yellow banner** appears at top: "Decision Maker requested changes: Please clarify the primary goal and secondary goals."
- [ ] ALL definition fields are still visible and editable
- [ ] Verdict buttons still present
- [ ] "Make Final Decision" section still visible (DM can still Accept later)

6. Click **"+ Add comment"** on the Overall Feedback section
7. Type a comment and post it

**Expected:**
- [ ] Comment posts without page refresh
- [ ] Comment appears in the overall feedback section

---

## Step 9 — Contributor Edits a Field (log in as Contributor)

1. Log in as the Contributor
2. Go to the portal — confirm the DM yellow banner is visible
3. Click **"✏ Edit"** next to the Primary Goal field
4. Change the text, click **Save**

**Expected:**
- [ ] Field saves in-place (no page reload needed)
- [ ] New value shows immediately

5. After the field saves, try clicking **"+ Add comment"** on that same field

**Expected:**
- [ ] Comment form opens — no page refresh needed
- [ ] Comment posts successfully

---

## Step 10 — DM Accepts (log in as DM)

1. Log in as DM
2. Go to portal — verify the edited Primary Goal value is shown
3. Optionally add a note, then click **"Accept"**

**Expected:**
- [ ] Full page reload
- [ ] Green banner: "Definition approved!"
- [ ] Definition fields shown read-only below banner
- [ ] Verdict buttons / DM decision section gone

---

## Step 11 — Admin Locks the Definition

1. Log in as Admin
2. Go to project detail → Phase 2 panel

**Expected:**
- [ ] Status badge: "Client Approved" (green)
- [ ] Amber banner: "The client has approved the Project Definition. Lock it now to proceed."
- [ ] "Lock Definition" button present
- [ ] "Reset to Draft" button NOT shown (already approved)

3. Click **"Lock Definition"** → confirm

**Expected:**
- [ ] Status badge: "Locked" (green)
- [ ] Definition fields shown as read-only
- [ ] "Send to Client for Review" and "Lock Definition" buttons gone

---

## Step 12 — Admin "Reset to Draft" Escape Hatch

(Test this separately with a different project, or at the start before advancing)

1. Create a second test project (or reuse one in Qualification stage)
2. Go through Steps 5–6 to send the definition for review
3. In the admin Phase 2 panel, click **"Reset to Draft"**
4. Confirm in the dialog

**Expected:**
- [ ] Page reloads
- [ ] Status badge: "Draft"
- [ ] "Send to Client for Review" button back
- [ ] "Reset to Draft" button gone
