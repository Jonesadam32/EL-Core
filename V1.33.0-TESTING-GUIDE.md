# v1.33.0 Testing Guide — User Journey Assignment Flow

**Plugin:** EL Core v1.33.0  
**Approach:** One project advanced through to Stage 4. Test the full assignment flow end to end.

**What's new in v1.33.0:**
- Admin "Send List to Client" button in Phase 4 panel
- Portal Stage 4 replaced with real DM assignment UI + stakeholder 5-question form
- Round 1 AI fires automatically after stakeholder submits answers

---

## Setup Before You Start

1. Upload `el-core-v1.33.0.zip` via WordPress Admin → Plugins → Add New → Upload Plugin
2. Verify plugin shows "EL Core 1.33.0"
3. Have three users ready:
   - **Admin** — your WP admin account
   - **DM** — a test user who will be the Decision Maker
   - **Contributor** — a second test user who will answer journey questions

---

## Step 1 — Advance an Existing Project to Stage 4 (as Admin)

Use a project that already has:
- A locked definition (so `user_types` is set — this seeds the journey rows)
- An accepted proposal (Stage 3 complete)

If you don't have one, create a project, complete Stages 1–3, then advance to Stage 4.

1. In WP Admin → Expand Site, open the project
2. Click **Advance to Stage 4 (User Journey)**
3. Go to the **Phase 4** tab in the project detail page

**Expected:**
- Phase 4 tab is now active
- Journey cards appear (one per user type from the locked definition)
- Each card shows status "Awaiting Assignment"
- Progress badge shows "0 of X journeys locked"
- Phase 5 gate notice is visible: "Visual Identity will unlock once all journeys are locked."
- **"Send List to Client" button** is visible in the panel header (blue/primary)

---

## Step 2 — Admin Reviews and Optionally Edits the User Type List

1. Look at the seeded user types — confirm they match what was in the definition's `user_types` field
2. If any user type looks like a combined entry (e.g. "Students and Teachers"), use **Add User Type** to add them individually, then delete the combined row
3. Don't advance yet — first verify the portal shows the "not ready" state

**Portal check (before sending list):**
1. Log in as DM and navigate to the portal
2. Click to Stage 4
3. **Expected:** "Your project manager is reviewing the list of user types and will notify you when it's ready for your team's input." — no cards visible

---

## Step 3 — Admin Sends List to Client

1. Back as Admin in the Phase 4 panel
2. Click **Send List to Client**
3. Confirm the dialog
4. **Expected:**
   - Button disappears
   - Green "List sent to client" badge appears in its place
   - Page reloads to the Phase 4 tab

**Portal check (after sending list):**
1. Log in as DM and navigate to Stage 4
2. **Expected:** Journey cards appear — one per user type
3. Each card shows:
   - User type name (bold)
   - "Unassigned" in muted/italic text
   - "Awaiting Assignment" badge
   - For DM: assignment dropdown + "Assign" button visible
   - For non-DM stakeholder: "Waiting for the Decision Maker to assign a team member."

---

## Step 4 — DM Assigns a Stakeholder (as DM in the portal)

1. Log in as DM, navigate to Stage 4
2. On the first journey card, select the **Contributor** from the assignment dropdown
3. Click **Assign**
4. **Expected:**
   - Page reloads
   - Card now shows the Contributor's name as the assignee
   - Status badge changes to "Awaiting Input"
   - Card body shows "Waiting for [Contributor Name] to complete this journey."
   - DM sees "Reassign to a different team member" link

5. Test the **Reassign** flow:
   - Click "Reassign to a different team member"
   - **Expected:** A dropdown + Reassign button slide into view
   - Select a different user, click Reassign
   - Page reloads with the new assignee shown
   - **Reassign back** to the Contributor before proceeding

---

## Step 5 — Assigned Stakeholder Sees the Question Form

1. Log in as the **Contributor**
2. Navigate to Stage 4 in the portal
3. Find the journey card they're assigned to
4. **Expected:**
   - Intro line: "You've been asked to describe the journey for: [User Type]."
   - 5 questions visible, each with bold question text and italic "For example:" helper text below it
   - 5 textareas, all empty
   - "Submit My Input" button is **disabled** (greyed out)

5. Test the form validation:
   - Fill in 4 of the 5 fields — button should remain disabled
   - Fill the 5th field — button should become **enabled**
   - Clear one field — button should go disabled again

---

## Step 6 — Stakeholder Submits Answers

1. Fill in all 5 answers (any text will do for testing)
2. Click **Submit My Input**
3. **Expected:**
   - Button changes to "Submitting…" and is disabled
   - Status text "Generating workflow…" appears next to the button
   - After response: form is replaced with a success message ("Thank you! Our team will review and build out this workflow.")
   - No page reload required

4. Reload the page and check the card again
5. **Expected:** Card shows "In Review" or "Processing" badge (status = `ai_generated`)
6. Card body shows: "Our team is reviewing and building out this workflow. Check back soon." with a spinner/update icon

---

## Step 7 — Admin Sees AI Output in Phase 4 Panel

1. Log in as Admin, open the project, go to Phase 4 tab
2. Find the journey card that was just submitted
3. **Expected:**
   - Status badge shows `AI Generated` (yellow/orange)
   - Card is expandable — click to expand
   - "What the team described" section shows the 5 Q&A pairs
   - "AI-generated workflow" section shows: summary sentence, numbered step list (5–10 steps), implied pages list, open questions (if any, in amber)
   - Mermaid flow diagram rendered below the workflow
   - Admin Notes textarea and "Refine with AI" button present

*(If AI is not configured, the card should still show the Q&A pairs with an error message about AI.)*

---

## Step 8 — DM Cannot Reassign After Submission

1. Log in as DM, navigate to Stage 4
2. Find the submitted journey card
3. **Expected:** No "Assign" or "Reassign" controls visible — card shows the processing state, not an assignment UI
4. *(The DM can still reassign on any other cards that are still in `awaiting_input` status)*

---

## Step 9 — Other Viewers See Correct States

Log in as any other stakeholder (not the assigned one, not the DM):

- **`pending_assignment` cards:** "Waiting for the Decision Maker to assign a team member to this journey."
- **`awaiting_input` cards (assigned to someone else):** "Waiting for [Name] to complete this journey."
- **`ai_generated` / processing cards:** "Our team is reviewing and building out this workflow. Check back soon."

---

## Step 10 — Edge Cases

### No journey rows yet (before Stage 4 advance)
- Portal Stage 4 shows "Your project manager is finalizing the user type list."

### Admin hasn't clicked "Send List to Client" yet
- Portal shows "Your project manager is reviewing the list..." regardless of whether rows exist

### "Send List to Client" doesn't appear
- Confirm: at least 1 journey row exists AND `journey_list_approved_at` is NULL on the project

### DB migration check
- In phpMyAdmin or wp-cli: `DESCRIBE el_es_projects;`
- **Expected:** `journey_list_approved_at` column exists as DATETIME NULL

---

## What's NOT Tested in This Version

- The consensus review portal (Step C) — `in_review` state with per-step comments, DM decision, and verdicts — that's the next build
- Admin Phase 4 editing (rename/delete user type rows) — already built in v1.31.0, not changed here
- Round 2 AI refinement — already built in v1.31.0, not changed here
