# v1.30.2 Testing Guide — Single Project, Start to Finish

**Plugin:** EL Core v1.30.2  
**Approach:** One project, tested from creation through definition approval. Follow steps in order.

**What's new in v1.30.2:**
- Phase bar pill now auto-highlights after Advance Stage (no manual click needed)
- Verdict buttons renamed: "✓ Approve Field" / "⚑ Flag for changes" + help text added
- Client profile Contacts table shows "Project Role" column
- Approved-state notice confirms admin can still edit before locking
- Draft-state notice explains when "Reset to Draft" button appears

---

## Setup Before You Start

1. Upload `el-core-v1.30.2.zip` via WordPress Admin → Plugins → Add New → Upload Plugin
2. Verify plugin shows "EL Core 1.30.2"
3. Have three users ready:
   - **Admin** — your WP admin account
   - **DM** — a test user who will be the Decision Maker on the portal
   - **Contributor** — a second test client user

---

## Step 1 — Create a New Project (as Admin)

1. Go to WP Admin → Expand Site → Create Project
2. Fill in project name (e.g., "Test Project 1.30.2") and client name
3. Click **Create Project**

**Expected:**
- [ ] Project is created and you're taken to the project detail page
- [ ] No blank white page

---

## Step 2 — Save the Qualification Intake (as Admin)

1. You should be on the project detail page, **Phase 1 (Qualification) pill is highlighted** (green underline) — this is the fix for Issue 1
2. Fill in the **Project Goal** field
3. Click **Save**

**Expected:**
- [ ] Phase 1 pill has its active visual style (green underline) without clicking it
- [ ] Button shows "Saving…" briefly, then "Saved ✓" for 2 seconds
- [ ] No page reload

---

## Step 3 — Draft-State Notice (as Admin, still in Phase 2 area)

1. Click **Advance to Stage 2** (top right) to move to Discovery
2. Once on Phase 2, look below the status badge

**Expected:**
- [ ] A blue info notice: *"This definition is in draft. Fill in the fields and click 'Send to Client for Review' when ready. The Reset to Draft button appears only after you've sent a review to the client."*
- [ ] Phase 2 pill is highlighted (active) — Issue 1 fix

---

## Step 4 — Add Stakeholders (as Admin)

1. Click the **Stakeholders** utility tab
2. Add the DM user as **Decision Maker**
3. Add the Contributor user as **Contributor**

**Expected:**
- [ ] No HTTP 400 errors
- [ ] Both users appear with correct role badges

---

## Step 5 — Check Client Profile Role Column (as Admin)

1. Go to WP Admin → EL Core → Clients → [your test client]
2. Look at the **Contacts** table

**Expected:**
- [ ] Table has a **"Project Role"** column (Issue 4 fix)
- [ ] The DM contact shows "Decision Maker" badge + project name
- [ ] The Contributor contact shows "Contributor" badge + project name
- [ ] Contacts with no project role show "—"

---

## Step 6 — Paste Transcript and Process (as Admin)

1. In Phase 2 (Discovery), paste any text into the **Transcript** textarea
2. Click **Process with AI**

**Expected:**
- [ ] AI extracts fields and populates them
- [ ] You can edit the fields
- [ ] Click **Save Definition** — shows success message

---

## Step 7 — Send Definition for Review (as Admin)

1. In Phase 2, click **Send to Client for Review**
2. Set a deadline 7 days from now
3. Click **Send for Review**

**Expected:**
- [ ] Status badge changes to "Sent for Review" (blue)
- [ ] "Send to Client for Review" button disappears
- [ ] "Reset to Draft" button appears (ghost style)
- [ ] The draft-state notice is gone (it was only for draft status)

---

## Step 8 — Contributor Reviews and Uses New Verdict Buttons

1. Log in as the Contributor user
2. Go to the client portal page for this project
3. Scroll to the **Project Definition — Review** section

**Expected:**
- [ ] Review section loads with all definition fields
- [ ] Above each field's verdict buttons, there is a help text: *"Use these to flag individual fields for the team's attention. The Decision Maker makes the overall final decision below."*
- [ ] Verdict buttons are labeled **"✓ Approve Field"** and **"⚑ Flag for changes"** (Issue 3 fix — old labels were "Looks good" / "Needs revision")

4. Click **"✓ Approve Field"** on the **Site Description** field

**Expected:**
- [ ] Button highlights green (active state) immediately
- [ ] Review section reloads in-place
- [ ] After reload, the "✓ Approve Field" button is STILL highlighted (Issue 2 fix — active state persists after refresh)
- [ ] Only ONE verdict indicator — not two (double checkmark fix from v1.30.1 still holds)

5. Refresh the entire page (F5)

**Expected:**
- [ ] After full page reload, `loadReview()` runs and the **"✓ Approve Field" button for Site Description is still highlighted green** — the active state is restored from the server

6. Click **"⚑ Flag for changes"** on the **Primary Goal** field

**Expected:**
- [ ] Button highlights amber (active state)
- [ ] No yellow banner appears (flagging a field is NOT the DM's overall decision — just a contributor marker)

7. Click **"+ Add comment"** on any field, type a comment, post it

**Expected:**
- [ ] Comment posts without page refresh
- [ ] Then click the verdict button on the same field — it saves in-place

---

## Step 9 — DM Reviews: Needs Revision

1. Log in as the DM user
2. Go to the client portal
3. Scroll to the Project Definition review section

**Expected:**
- [ ] "Make Final Decision" section at the bottom (DM only)
- [ ] Verdict buttons show "✓ Approve Field" / "⚑ Flag for changes" (same new labels)

4. Type a note: "Please clarify the primary goal."
5. Click **"Needs Revision"**

**Expected:**
- [ ] Review UI reloads in-place (no full page reload)
- [ ] Yellow banner appears: "Decision Maker requested changes: Please clarify the primary goal."
- [ ] ALL fields still visible and editable
- [ ] "Make Final Decision" section still visible

---

## Step 10 — DM Accepts

1. Log in as DM
2. Click **"Accept"** in the Make Final Decision section

**Expected:**
- [ ] Full page reload
- [ ] Green banner: "Definition approved!"
- [ ] Verdict buttons / DM decision section gone

---

## Step 11 — Admin: Approved State Editing Notice

1. Log in as Admin
2. Go to project detail → Phase 2 panel

**Expected:**
- [ ] Status badge: "Client Approved" (green)
- [ ] Amber banner: "The client has approved the Project Definition. Lock it now."
- [ ] Blue info notice: *"The client has approved this definition. You can still make final edits below before locking."* (Issue 5 fix)
- [ ] Definition fields are **editable** (not read-only)
- [ ] "Save Definition" button present

3. Edit one field and click **"Save Definition"**

**Expected:**
- [ ] Save succeeds
- [ ] Field is updated

4. Click **"Lock Definition"** → confirm

**Expected:**
- [ ] Status badge: "Locked" (green)
- [ ] Fields shown as read-only
- [ ] No edit/save/send buttons

---

## Step 12 — Admin: Reset to Draft Escape Hatch

1. Create a second test project and advance to Stage 2
2. Process transcript and send for review
3. In Phase 2, click **"Reset to Draft"** → confirm

**Expected:**
- [ ] Page reloads
- [ ] Status badge: "Draft"
- [ ] Blue draft-state notice appears: "This definition is in draft. Fill in the fields and click 'Send to Client for Review' when ready..."
- [ ] "Send to Client for Review" button back
- [ ] "Reset to Draft" button gone
